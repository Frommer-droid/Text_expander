# Руководство разработчика (DEVELOPER.md)

## 1. Обзор проекта

**Text Expander** — это приложение для автоматической замены текста (сниппетов) с графическим интерфейсом на базе **PySide6**. Программа отслеживает ввод с клавиатуры (используя `pynput`) и автоматически заменяет заданные аббревиатуры на полный текст.

### Основные возможности:
- Управление сниппетами (создание, редактирование, удаление).
- Импорт и экспорт сниппетов, настроек и общего backup-файла через JSON из вкладки `Система`.
- Масштаб интерфейса: авто-расчет от рабочей области экрана и DPI плюс ручная поправка пользователя.
- Аббревиатуры на основе скан-кодов клавиатуры (независимо от раскладки).
- **`logo.ico`**: Многомасштабная иконка приложения для окна, трея и сборки.
- **`app/assets/app-icon.svg`**: Векторный исходник иконки. Его фон намеренно
  непрозрачен и доходит до краёв холста, чтобы значок не выглядел маленьким в
  ярлыке или трее.

## 2. Структура проекта

- **`Text_expander.pyw`** — тонкая точка входа (инициализация и запуск).
- **`app/core/`** — бизнес-логика и оркестрация. Модуль `localization.py` отвечает за подключение русских Qt-переводов.
- **`app/ui/`** — интерфейс и логика GUI. Модули `ui_scale_mixin.py`, `ui_scale_runtime.py` отвечают за runtime-масштабирование, обязательная тема OneDark Pro — пакет `app/ui/theme/` (`apply_theme` сразу после `QApplication`, роли кнопок через `objectName`, `enforce_button_proportions` для икончатых).
- **`app/services/`** — сервисы (слушатель клавиатуры, WinAPI, пути, логирование, формулы масштаба).
- **`app/services/data_exchange_service.py`** — чтение, проверка и атомарная запись JSON для импорта/экспорта и общего backup-файла.
- **`app/services/ui_scale_service.py`** — чистые формулы масштаба, нормализация `ui_scale_*` и миграция старого `ui_scale_percent`.
- **`app/utils/`** — общие утилиты и вспомогательные функции.
- **`app/version.py`** — источник версии для GUI и сборки.
- **`VERSION`** — номер версии в dev-режиме.
- **`tests/`** — минимальные автоматические тесты для локальных функций без запуска GUI, включая формулы масштаба, QSS и JSON-валидацию.

## 3. Требования к окружению

Для разработки и запуска требуется проектное окружение **`.venv`** на **Python 3.12** и следующие библиотеки:

- `PySide6` — графический интерфейс.
- `pynput` — перехват нажатий клавиатуры.
- `pywin32` — взаимодействие с Windows API (определение активного окна, работа с буфером обмена и треем).
- `psutil` — получение информации о процессах.
- `pyperclip` — работа с буфером обмена (кроссплатформенная обертка).
- `PyInstaller` — сборка portable-версии.
- `pytest` — базовые автоматические тесты.

### Установка зависимостей:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

### Настройка IDE

Для VS Code в репозитории хранится `.vscode/settings.json`, который указывает интерпретатор на `${workspaceFolder}\.venv\Scripts\python.exe`.

## 4. Запуск и отладка

Для запуска приложения из исходного кода выполните команду:

```powershell
Start-Process .\.venv\Scripts\pythonw.exe -ArgumentList ".\Text_expander.pyw"
```

> **Примечание:** Для корректной работы функций автозамены и перехвата клавиш в некоторых приложениях (и для записи в автозагрузку) может потребоваться запуск **от имени администратора**. Скрипт автоматически пытается перезапустить себя с повышенными правами, если это необходимо.

Перед созданием окон приложение загружает русские Qt-переводы через `QTranslator` и `qtbase_ru.qm`, чтобы стандартные меню и диалоги Qt были на русском языке как в dev-режиме, так и в собранной версии.

Если `.pyw` по ошибке запускают через `python.exe`, точка входа автоматически перезапускает приложение через `pythonw.exe`, чтобы не открывать консольное окно.

### Тесты

```powershell
.\.venv\Scripts\python.exe -m pytest
```

## 5. Подготовка сборки

Приложение собирается в onedir-папку: `Text_expander.exe`, `_internal` и ресурсы.
Spec-файл находится в `Build_Tools/Text_expander.spec`, GUI-сборщик — в
`Build_Tools/SpecCompiler.pyw`. Spec проверяет происхождение каждой native DLL
или extension из `Analysis.binaries` и останавливает сборку при постороннем пути.

Обязательный порядок для Windows-сборки:

1. Запускать PyInstaller из проектной `.venv` с минимальным `PATH`: окружение,
   runtime Qt, базовый Python и его DLLs, Windows System32.
2. Проверять источники `Analysis.binaries`: проект, выбранный Python/venv,
   Windows или явно разрешённый runtime. Посторонняя DLL должна останавливать сборку.
3. До очистки build-папки проверить `COLLECT-00.toc`:
   `python Build_Tools/verify_frozen_windows.py --project-root . --toc Build_Tools/build/Text_expander/COLLECT-00.toc`.
4. После `post_build.py` выполнить
   `python Build_Tools/verify_frozen_windows.py --app-dir Text_expander`; команда сверяет
   root `_internal` MSVC runtime с PySide6 и запускает неинтерактивный frozen smoke-test
   с проверкой stdout, stderr и exit code. Smoke-путь не запрашивает UAC и не создаёт GUI.
5. Только после проверки запускать post-build и удалять рабочие файлы PyInstaller.

`Build_Tools/post_build.py` ожидает onedir в `Build_Tools/dist/Text_expander`,
переносит результат в корневую папку `Text_expander/`, добавляет VERSION, иконку,
MIT и сторонние лицензии, формирует `RUNTIME_MANIFEST.json`.

Публичные данные создаются заново: `snippets.json` — пустой объект,
`expander_settings.json` — автозапуск и запуск в трее отключены.
Личные JSON из корня проекта не копируются и не изменяются. Не запускайте
post-build поверх рабочей portable-папки с единственной копией пользовательских данных.

Spec и post-build исключают неиспользуемый Qt Virtual Keyboard/QML/Quick runtime.
Перечень компонентов и тексты лицензий находятся в `THIRD_PARTY_NOTICES.md` и `licenses/`.
Существующий релиз v5.16.0 содержит только исходники; новый бинарник в рамках
оформления репозитория не собирался.

Личные скрипты создания установщика и копирования portable-папки не входят в
публичный репозиторий. Для своего установщика используйте проверенную чистую
сборку и подходящий сборщик установщиков, сохраняя лицензии зависимостей.

## 6. Архитектура и ключевые классы

### `TextExpanderApp` (QMainWindow) — `app/ui/main_window.py`
Главный класс приложения. Отвечает за:
- Инициализацию GUI (вкладки, дерево сниппетов, редактор).
- Загрузку и сохранение настроек и сниппетов.
- Импорт и экспорт `snippets.json`, `expander_settings.json` и объединённого backup JSON.
- Применение масштаба интерфейса, включая QSS, layout-метрики и реакцию на изменения экрана/DPI.
- Обработку событий трея и автозапуска.
- Управление потоком слушателя.

### Масштаб интерфейса
Настройки масштаба хранятся в `expander_settings.json`:
- `ui_scale_mode` — сейчас нормализуется в `auto`;
- `ui_scale_delta_percent` — ручная поправка пользователя от `-50` до `50` с шагом `10`;
- `ui_scale_percent` — последний рассчитанный итоговый процент для диагностики и экспорта.

Также в `expander_settings.json` хранится `window_filter_collapsed` (bool) — свёрнутость
блока «Фильтр по окну» в правой панели главного окна; участвует в экспорте/импорте настроек.

Авто-масштаб рассчитывается от `QScreen.availableGeometry()` и `logicalDotsPerInch()` относительно базового экрана `2560x1440 @ 96 DPI`. Ручная смена масштаба сразу перестраивает QSS, layout-отступы, минимальные размеры и ширину служебной колонки дерева. При смене монитора, DPI или топологии экранов масштаб пересчитывается без принудительного resize окна.

### `ListenerWorker` — `app/services/listener_worker.py`
Класс, работающий в отдельном потоке (`threading.Thread`).
- Инициализирует `pynput.keyboard.Listener`.
- Отслеживает нажатия клавиш и формирует буфер скан-кодов.
- Проверяет буфер на наличие аббревиатур.
- Выполняет замену текста (эмуляция через WinAPI SendInput и вставка через буфер обмена).
- Содержит специальную логику для `winword.exe` (Microsoft Word).

### `app/services/scan_code_keyboard.py`
Модуль для работы со скан-кодами клавиатуры.
- Преобразует аббревиатуры в последовательности скан-кодов.
- Формирует индекс сниппетов по скан-кодам.
- Отправляет ввод через WinAPI `SendInput`.

### `SnippetTreeWidget` (QTreeWidget) — `app/ui/snippet_tree_widget.py`
Кастомизированный виджет дерева.
- Реализует логику Drag-and-Drop для перемещения сниппетов и категорий.
- Обрабатывает сигналы перемещения элементов.
- Обновляет редактор только при подтверждённом выборе: клике, клавиатурной навигации
  или явном программном выборе; простое наведение курсора ничего не меняет.

## 7. Правила разработки (Code Style)

- **Язык**: Весь код, комментарии и документация должны быть на **русском языке**.
- **Форматирование**: Соблюдение стандартов PEP8.
- **Версионирование**: При релизе обновляйте `VERSION` (dev), `app/version.py` (FROZEN_VERSION для .exe) и `RELEASE_NOTES.md`.
